## What This Does

TakeMeter is a supervised text classifier for real programming questions from the public Stack Overflow community, selected using the `python` tag. It learns to distinguish questions primarily about fixing existing broken code (`debugging`), accomplishing a programming task (`implementation`), and understanding why a language or tool works a certain way (`conceptual`).

The current dataset contains 220 complete question posts collected using the public Stack Exchange API. I am using the starter `takemeter.ipynb` notebook for a stratified 70/15/15 train/validation/test split and fine-tuning `distilbert-base-uncased` on my local machine. The local training result was generated by the original Unit 5 notebook; actual metrics are recorded in `results.json` and the held-out data is saved in `test_split.csv`.

---

## Label Taxonomy

### `debugging`

**Definition:** A post reporting a failure, error, crash, or unexpected result in code or a system already being used, and seeking to find or fix the cause.

**Real-post examples (titles):**

- "Screen blanks after executing .py file in Geany"
- "Playwright installation fails on Linux Mint Gigi"

### `implementation`

**Definition:** A post primarily asking how to write, configure, change, or complete a concrete programming task or desired feature, without a current malfunction as its main focus.

**Real-post examples (titles):**

- "How can I color specific words in live time in a QTextEdit?"
- "How to get both losses and detection predictions from Torchvision Faster R-CNN in training mode and vice versa?"

### `conceptual`

**Definition:** A post primarily asking how or why a language, library, tool, algorithm, design choice, or programming concept behaves, rather than requesting a particular fix or implementation.

**Real-post examples (titles):**

- "Does importing modules which are only used for type-checking have any runtime overhead?"
- "Where is the Python documentation for handling ties with the built-in min function?"

### Hardest boundary and decision rule

**Boundary:** `debugging` vs. `implementation` (a request to *fix* behavior versus a request to *build* behavior).

**Proposed rule to apply consistently:** If the post says an existing program produced an error or an unexpected output, assign `debugging`, even if it asks "how can I". If the current behavior is not presented as broken and the author is seeking a new feature or way to perform a task, assign `implementation`. Assign `conceptual` if the request is mainly for reasoning or an explanation and neither a fix nor a new implementation is the primary deliverable.

## The Dataset

**Source:** Public Stack Overflow questions tagged `python`, collected from the Stack Exchange API. Source IDs and URLs are saved in `raw_posts.csv` on my local machine. Complete post text is preserved in `labels.csv` (including long questions and code). There are 220 unique posts; the classification file has exactly the `text`, `label`, and `note` columns required by the assignment.

**Annotation workflow:** The first 20 posts were independently cold labeled in the local project. The remaining 200 currently have AI-suggested classifications that need to be checked and corrected individually. **Potential hard cases for manual adjudication:**

3. "How to get both losses and detection predictions from Torchvision Faster R-CNN in training mode and vice versa?" — `implementation` versus `conceptual`. The question seeks a specific way to obtain multiple program outputs, so the suggested label is `implementation`.

## The Training Run

**Starter base model:** `distilbert-base-uncased`.

**Planned settings:** 3 epochs, learning rate 2e-5, batch size 16, maximum input length 128 tokens, seed 42, and a 70/15/15 stratified split. These are the provided notebook defaults; they are not claimed as an already-completed run.

**Environment:** The local `.venv` inside the existing TakeMeter fork in VS Code. `python test.py` checks dependency and device availability before notebook execution. **Device:** cpu.

**Actual training:** completed locally. Held-out accuracy: 0.5151515151515151, macro F1: 0.22666666666666668. The exported metrics are in `results.json`; the held-out data is in `test_split.csv`.

**Moment 1 — Dataset preparation:** I used AI to help create a data collector using the Stack Exchange API after a Reddit collection attempt returned HTTP 403. The collector downloaded 220 public Stack Overflow question posts and wrote the required `labels.csv` file. The downloaded posts were real public questions, not AI-generated examples.

**Moment 2 — Taxonomy and draft annotation:** I used AI to propose a three-label taxonomy, a consistent boundary rule, and provisional classifications for 200 posts. I must independently label the first 20 without seeing AI suggestions, read and correct all 200 AI-suggested classifications, and finalize the acceptance criteria before training.

**Pre-labeling disclosure:** Rows 21–220 were AI-pre-labeled and are explicitly marked `AI pre-labeled; student review required`; rows 1–20 have blank labels and `cold` notes until I independently complete them. I must not claim AI pre-labels are human reviewed until I actually check them.
